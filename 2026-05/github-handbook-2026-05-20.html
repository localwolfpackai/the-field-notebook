00 · Premise

If you can't put it on GitHub, you can't really build with AI.

Here's the unlock: every serious AI tool — Claude Code, Codex, Cursor, Copilot — assumes you live inside a git repo. Your AI gets 10x sharper the moment it can see history, branches, diffs, and the blame trail. The repo is the memory.

I'm a sales-trained operator who can't write a recursion to save my life. GitHub didn't click for me as a developer tool. It clicked as a journal with superpowers: every save is timestamped, every change is reversible, every collaborator (human or agent) sees the same source of truth.

Hot take

Stop thinking of git as version control. Think of it as checkpoints in a video game. You're going to die. The point is to die having saved recently. Everything else is terminology getting in your way.

01 · Setup

The ten-minute starter pack.

Three installs, one auth flow, one repo. Do this once and you never have to think about it again.

  1. Install Homebrew if you haven't

    Homebrew is the package manager that makes installing CLI tools a single command. If you're on a Mac and you don't have it yet, paste this into Terminal.

    terminal
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

  2. Install git and the GitHub CLI

    git is the local engine. gh is the polished wrapper that talks to github.com — creating PRs, opening issues, viewing checks. You want both.

    terminal
    brew install git gh

  3. Authenticate once

    This logs you in via browser. Pick HTTPS, pick "Login with web browser", paste the code, done.

    terminal
    gh auth login

    Field note

    Once gh is authed, regular git push commands work too — gh handles the credential dance behind the scenes. This is the single biggest reason beginners get stuck. Skip gh and you'll spend two hours fighting SSH keys.

  4. Set your identity

    This is just so commits have your name on them. Replace with your real values.

    terminal
    git config --global user.name  "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main

  5. Make your first repo

    From inside any project folder. gh repo create handles both the local and remote in one shot.

    terminal
    cd ~/my-project
git init
gh repo create --public --source=. --remote=origin --push

    You now have a repo on github.com. Pull it up in your browser. That's it. You're in.

02 · Daily moves

The four commands that cover 90% of the work.

Forget the 30-command cheat sheets. Here's the loop I actually run, in order, every day.

See what changed

git status

What's modified, what's staged, what's untracked. Your dashboard. Run it constantly.

git status
Stage + commit

git add + git commit

Save a checkpoint. Write commit messages like you're texting future-you at 2am.

git add .
git commit -m "fix: header padding on mobile"
Send it up

git push

Pushes your local commits to GitHub. First push on a new branch wants -u origin branchname; after that it's just git push.

git push -u origin main
Pull others' work

git pull

Grab anything new from GitHub. If you're solo, you'll rarely need it. The second you collaborate (or use codespaces, or push from your phone), it's the move.

git pull

The mantra

status → add → commit → push. Four words. That's the loop. Tape it to your monitor. The fancy stuff — rebasing, cherry-picking, interactive history surgery — is for when you've earned the right to break things on purpose.

03 · Pull requests

Your first PR, the lazy way.

A pull request is a proposal: "here's a change, please review it before it lands." Even solo, PRs are useful — they're the natural unit of work, and the AI tools all key off them. Branches → PRs → merge. That's the rhythm.

  1. Branch off main

    Name it after what you're doing. Kebab-case. Short.

    git checkout -b add-pricing-page

  2. Make your changes, then commit

    git add .
git commit -m "feat: pricing page hero + tiers"

  3. Push the branch up

    git push -u origin add-pricing-page

  4. Open the PR from the terminal

    This is where gh earns its keep. Skips the browser entirely.

    gh pr create --title "Pricing page" --body "Adds tier comparison + CTA"

    You'll get a URL. Open it. Watch CI run. Merge it when you're happy.

  5. Merge and clean up

    gh pr merge --squash --delete-branch
git checkout main && git pull

    --squash flattens all your messy in-progress commits into one clean one on main. --delete-branch tidies up.

The AI handshake

This is the exact loop Claude Code, Codex, and Cursor expect. They love small, scoped PRs because they fit in context windows. Train yourself on small PRs early — you're not just learning git, you're learning how to collaborate with agents.

04 · Safety

Git safety in the agent era.

AI coding assistants will execute git push --force if you let them. Here are the rails I keep up. None of this is paranoid — it's just earned.

  • Never amend a published commit

    Amending changes history. If you've already pushed, amending rewrites what others (or your other machines) already have. Use git revert instead — it makes a new commit that undoes the old one.

    # instead of: git commit --amend
git revert <commit-sha>

  • Stash before you experiment

    About to try something wild? Stash first. It's a temporary save you can pop back any time.

    git stash               # save current changes
# ...try the wild thing...
git stash pop           # bring them back

  • Read diffs before commits

    Two seconds of git diff catches the console.log you forgot, the API key you almost shipped, the half-finished sentence in a CHANGELOG.

    git diff --staged

  • Never push .env

    Add this to your .gitignore before your first commit. Once secrets land on GitHub, treat them as compromised — even if you delete them later, they're in the history.

    # .gitignore
.env
.env.local
.env.*.local
node_modules/
.DS_Store

  • Tell your AI the rules

    If you're using Claude Code or similar, put guardrails in CLAUDE.md at the repo root. Mine includes:

    ## Git Safety
- Never run `git push --force` without explicit confirmation
- Never delete branches without confirmation
- Always run `git diff` before committing
- Use `git revert`, never `--amend`, on published commits
- Stop and ask before any destructive operation

Heard this one before

If a command starts with --force, --hard, or -D, slow down. Those are the three flags that have eaten more weekend work than any single mistake in tech. Read what's about to happen. Then read it again.

05 · Automation

Five GitHub Actions worth stealing.

GitHub Actions is your quiet coworker. The mental model is one sentence: when X happens in the repo, do Y automatically. A push, a PR, a label, a schedule — any of those can be your X. Here are the five I install on every project.

01
Run tests on every PR
Catches breakage before merge. Even one passing test gates real bugs from shipping. The cheapest insurance you can buy.
02
Auto-deploy on push to main
Vercel, Netlify, Cloudflare Pages — all do this natively. Your git push is your deploy. Closes the loop between editor and production.
03
Lint and format checks
Biome or ESLint + Prettier runs on every PR. Stops style debates dead. Your code looks the same as your collaborators' code, automatically.
04
Triage labels on new issues
Auto-label by file path, title keyword, or author. Future-you opens the inbox and the work is already sorted.
05
Changelog + release notes
release-drafter assembles release notes from merged PRs. Tag a version, ship the notes, look professional. Zero manual writeup.

A starter workflow, top to bottom

Drop this in .github/workflows/ci.yml. It runs on every PR. It's deliberately simple — start here and add only when something breaks.

.github/workflows/ci.yml
name: CI

on:
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npm test

The leverage move

Automation is pre-decisions. You decide once how the project handles a class of event, and it benefits every time forward. The win compounds.

07 · Cheat sheet

The page you screenshot.

Daily loop
git status
git add .
git commit -m "what i did"
git push
Branch + PR
git checkout -b my-branch
# ...edit, commit, push...
gh pr create
gh pr merge --squash --delete-branch
Oh no, undo
git diff                    # what changed?
git restore <file>          # discard a file's changes
git reset HEAD~1            # undo last commit, keep changes
git revert <sha>            # safely undo a published commit
git stash                   # set changes aside
git stash pop               # bring them back
Inspect history
git log --oneline -20       # last 20 commits, one line each
git log -p <file>           # full history of one file
git blame <file>            # who wrote each line, when
gh pr view --web            # open current PR in browser
Quick gh recipes
gh repo clone <owner>/<repo>
gh repo create <name> --public --source=. --push
gh issue create --title "Bug: X" --body "Y"
gh pr checkout 42           # check out PR #42 locally
gh run watch                # watch CI run live

08 · Going further

What to learn next, in order.

  1. Get fluent with gh

    Replace browser tabs with terminal commands one at a time. PRs, issues, releases, even repo creation. Velocity compounds.

  2. Write a real Action

    Pick one repetitive task — running tests, deploying, sending Slack notifications. Automate it. The first one is hardest. After that you'll see opportunities everywhere.

  3. Set up branch protection on main

    In Settings → Branches, require PRs before merging to main. Even solo, this is the move. It enforces the rhythm.

  4. Add a CLAUDE.md or AGENTS.md

    Document the repo's architecture, conventions, and safety rules in a markdown file at the root. Your AI assistants read it on every session. Future-you reads it on Monday mornings.

  5. Use Codespaces for the messy experiments

    A full dev environment in the browser, spun up from any repo, for free up to a limit. Perfect for "I want to try this on a fresh setup without messing up my laptop."

The point

You don't need to memorize git. You need to memorize four commands and one mantra: status → add → commit → push. Everything else is something you Google in the moment, once, ever. The rest of GitHub — PRs, Actions, the CLI — gets cheaper to use the more you use it. Start small. Ship often. Every L is a W.
