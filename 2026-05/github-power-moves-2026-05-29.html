GitHub power moves — thirteen hacks I wish I knew on day one.

Past notebooks covered the basics: clone, branch, commit, push, PR. This one is the next tier — the keyboard tricks, URL hacks, gh extensions, and tiny CLI sleight-of-hand that turn GitHub from a website into an actual workshop. Mostly browser-side. Mostly free. All learned the slow way so you don't have to.

—Lupo · The Mess is the Method
Read · ~14 min Surface · github.com + gh Assumes · you've made one repo Voice · open-notebook, casual

The basics get you shipping. The hacks get you fluent. Most of these are one keystroke, one URL suffix, or one gh extension install away — and once they're in your hands you can't go back. I learned almost all of these by watching someone hit a key I didn't recognize and going "wait, what just happened."

This isn't a list of things you should know. It's the list of things I picked up after the basics stopped slowing me down. Steal the ones that fit how you work. Skip the rest.

01

Press . on any repo — full VS Code, in your browser. browser

This is the one I show people first because nothing else lands as fast. Open any public repo — yours or someone else's — and tap the period key. The whole page swaps for a real github.dev editor. Same shortcuts, same find-in-files, same sidebar. No clone, no install.

address bar 
// before
https://github.com/cli/cli

// press "."
https://github.dev/cli/cli   ← full VS Code

I use it to read unfamiliar repos. Cmd-P, fuzzy-search for the file I'm looking for, jump in, read it, close the tab. Zero footprint. For your own repos you can even commit small edits straight from the browser — great for fixing a typo from someone else's laptop.

try it ↳
Go to github.com/anthropics/anthropic-cookbook right now, press ., and open README.md with ⌘+P. You're in an IDE on a repo you didn't clone. Wild.
02

Hit ? — every keyboard shortcut, one keystroke away. browser

Almost every page on github.com has a hidden shortcut overlay. Press the question mark and a panel slides up with every key for that context. The shortcuts change based on where you are — the issue list has different keys than a PR diff than a repo file tree. You don't need to memorize them; you need to remember the question mark.

g c
go to code — repo file tree
g i
go to issues
g p
go to pull requests
g n
notifications
y
pin SHA — locks the URL to current commit
b
blame view — on any file
l
edit labels — on an issue/PR
e
edit this file — opens the editor

the y trick alone is gold. Pinned URLs don't rot.

03

Press t — fuzzy file finder, inside the repo viewer. browser

Same energy as Cmd-P in VS Code, just for the repo you're currently looking at. You'll never click through folders again. Tap t, type part of a filename, hit enter.

github file finder 
/ CLAUDE
CLAUDE.md
src/agents/CLAUDE.md
docs/CLAUDE-EVALS.md

/ .env.example
.env.example

# enter → file opens. arrows → move. esc → bail.

Pairs ridiculously well with the . trick from #1 — press . for VS Code in browser, then ⌘+P to fuzz-find. Either way you stop scrolling file lists like a tourist.

04

URL hacks — /blame, /raw, /find and friends. browser

GitHub URLs are weirdly composable. Swap a segment and you get a different tool. Once you've seen the pattern you stop hunting for buttons.

/blame/main/path/to/file
Who wrote each line and when. Best context tool on the site.
/raw/main/path/to/file
Plain file contents. Pipe directly into curl or wget.
/find/main
Same as pressing t — fuzzy file finder.
/commits/main/path/to/file
Just the commits that touched this file. Surgical history.
/pulse
Activity dashboard for any repo — PRs merged, contributors, churn.
/network
Visualizes all forks and where they've diverged. Beautiful and underused.
/community
Profile completeness scorecard. Good template for your own repos.
?w=1
Append to any diff URL to hide whitespace changes. Lifesaver.
heads up ↳
For /raw on private repos use raw.githubusercontent.com instead — the regular github.com/.../raw redirects but breaks curl auth chains.
05

Search operators that actually work. browser

GitHub's search box is way more capable than the placeholder lets on. The trick is the qualifiers — key:value pairs that filter what you're scanning. These are the four I use weekly.

github search 
# my open PRs across every repo
is:pr author:@me is:open

# issues someone @ mentioned me on but I haven't replied to
is:issue mentions:@me -commenter:@me

# find every Dockerfile in a specific org
org:anthropics filename:Dockerfile

# code containing a phrase, in TypeScript only
"useChat" language:typescript path:**/hooks

# PRs touching one specific file in the last week
repo:owner/repo is:pr path:src/auth.ts merged:>2026-05-22

Two power-tips that took me embarrassingly long to learn: quote phrases with spaces, and prefix - for NOT. So is:pr -label:wip review-requested:@me = "ready for me, not a work-in-progress". Save the URL and you've got a permanent filtered inbox.

try it ↳
Run is:pr author:@me sort:updated-desc on github.com/pulls and bookmark the result. That's your real PR queue.
06

gh dash — a terminal dashboard for issues and PRs. terminal

The dlvhdr/gh-dash extension turns your shell into a TUI dashboard. Custom sections, vim keys, configurable filters. I have one tab for "needs my review", one for "my open PRs", one for "issues I opened". It refreshes when I hit r. Cheaper than checking the browser fifty times a day.

install + run 
$ gh extension install dlvhdr/gh-dash
$ gh dash

# config lives at ~/.config/gh-dash/config.yml
# add your own section:
prSections:
  - title: My PRs
    filters: is:open author:@me
  - title: Needs Review
    filters: is:open review-requested:@me

Bonus: gh dash respects your repo context. Run it inside a repo and it scopes to that one; run it from ~ and it spans everything.

07

gh copilot suggest + explain — a shell coach. terminal

If you have Copilot access, this is the underrated half of it. Not autocomplete — question/answer right in your terminal. suggest gives you the command you couldn't remember. explain tells you what the cryptic one-liner you pasted from Stack Overflow actually does.

gh copilot 
$ gh extension install github/gh-copilot

# ask for a command
$ gh copilot suggest "find all js files modified in the last 2 days"
Suggestion: find . -name "*.js" -mtime -2

# decode a wall of flags
$ gh copilot explain "tar -czvf backup.tgz --exclude='*.log' ./src"
Creates a gzipped tarball 'backup.tgz' from ./src,
excluding any files matching *.log. Flags:
  c → create  z → gzip  v → verbose  f → file
heads up ↳
Requires an active Copilot subscription. If you don't have one, gh copilot still installs but every call returns an auth error. Same vibe as man + Stack Overflow without the tabs.

09

gh alias set — your personal verbs. terminal

Tired of typing the same long gh pr ... incantations? Alias them. These are real shell-level commands; they show up in gh --help like first-class verbs.

my aliases 
# open the current branch's PR in the browser
$ gh alias set prv 'pr view --web'

# list my open PRs, one line each
$ gh alias set mine 'search prs --author=@me --state=open'

# merge with squash, delete branch, no questions asked
$ gh alias set shipit 'pr merge --squash --delete-branch'

# clone any repo by org/name without typing the URL
$ gh alias set get 'repo clone'

# use it ↓
$ gh get anthropics/anthropic-cookbook
$ gh mine
$ gh prv
$ gh shipit

You can also pass --shell to drop into raw shell — useful if your alias needs piping or arg substitution. Aliases sync per-machine, not per-account, so back up your ~/.config/gh/config.yml.

10

The profile README trick. workflow

Create a repo with the exact same name as your username, add a README.md, and GitHub renders it on your profile. That's the whole hack. Most profiles you've admired use this.

spin one up 
$ gh repo create localwolfpackai/localwolfpackai \
    --public --add-readme --clone

$ cd localwolfpackai
$ $EDITOR README.md   # write whatever you want
$ git add README.md && git commit -m "hello" && git push

Treat it like a one-page portfolio. Mine has a one-line tagline, three projects with screenshots, a contact section, and that's it. The repo itself is private to most people because they don't realize it exists — but anyone visiting github.com/<you> sees the README.

embed dynamic badges, GitHub stats cards, even a now-playing widget from Spotify if you want to flex.

11

Gists as a snippet library you actually keep. workflow

Gists are stripped-down repos for single files. They version, they have revision history, they accept comments, they're git-cloneable. I use them for: shell one-liners I'll forget, prompt templates, .zshrc fragments, and quick demos I want to share without spinning up a repo.

create & list from CLI 
# pipe a file straight into a private gist
$ gh gist create ~/scratch/oklch-helper.py --desc "oklch <-> hex"

# or paste straight from stdin
$ echo "alias gst='git status -sb'" | gh gist create --public --filename aliases.sh

# list yours, edit one in place
$ gh gist list
$ gh gist edit <id>

Star your favorites at gist.github.com/<you>/starred and they become a curated, searchable second brain. Way better than a Notes app for anything code-shaped.

12

Saved replies + draft PRs — the canned-response combo. workflow

Two features that compound when you use them together. Saved replies live at github.com/settings/replies and let you keyboard-insert canned text into any issue or PR comment. Draft PRs let you open the PR early without requesting review — great for parking work-in-progress somewhere visible.

The combo I run on every non-trivial PR:

flow 
# 1. open as draft so it doesn't spam reviewers yet
$ gh pr create --draft --title "feat: oklch utility" --body-file .pr.md

# 2. when ready, mark ready
$ gh pr ready

# 3. drop a saved reply for context, e.g. "testing notes"
#    GH UI: comment box → reply icon → pick template → ⌘+Enter

My most-used saved replies: "Tested locally, screenshots in PR body", "Open question — see comment thread", "Ready for re-review". None of them are clever. They just save fifteen seconds, thirty times a week.

13

gh repo view --web and friends — the "open this in the browser" shortcuts. terminal

The boring one I use the most. Half my context switches are "I want to look at this in the browser." These shortcuts cut every one of them to one command.

the --web family 
$ gh repo view --web        # open current repo
$ gh pr view --web          # open current branch's PR
$ gh issue view 42 --web    # open issue #42
$ gh browse                 # shortest spelling, same idea
$ gh browse src/index.ts    # open this file at HEAD
$ gh browse src/index.ts:42 # open file at a specific line
$ gh browse --commit         # open the current commit's page

The gh browse src/file:42 form is the one nobody talks about and everybody needs. Pair-coding, code-review, sharing exact lines in Slack — it generates the deep link without you scrolling.

try it ↳
From inside any repo, run gh browse README.md:1. That's the same URL you'd hunt for through three clicks — pinned to the line, pinned to HEAD. Copy, paste, ship.
