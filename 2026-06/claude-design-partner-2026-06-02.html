Designed, not generated — twelve moves for directing Claude like a design partner.

Last notebook covered building the app. This one is narrower and harder: making it look like a person made it. Claude can output a real interface from one sentence — but the default sentence gets you the default look. These are the moves I use to push past that: the design vocabulary, the visual knobs, the AI tells worth killing, and where Gemini still earns a seat. Mostly Artifacts. All learned by iterating in the panel until it stopped looking auto-generated.

—Lupo · The Mess is the Method
Read · ~13 min Surface · Claude Artifacts + a little Gemini Assumes · you've prompted one UI before Voice · open-notebook, casual

The model writes the markup. You direct the taste. That split is the whole job now, and almost nobody talks about the second half. A blank prompt gets you the house style — centered everything, a purple gradient, system fonts, padding that's either zero or a mile. Fine for a sketch. Embarrassing for a portfolio.

I'm not a developer by trade. I supply direction, the model supplies the floor, and the gap between "generated" and "designed" turns out to be vocabulary — knowing the words for what you can already see is off. Say "more editorial," "tighter rhythm," "warmer paper," and Claude moves in a specific, repeatable direction.

Format below: each move gets a number, a one-line claim, a real prompt or comparison, and a try-it crumb. The closer to the top, the more I reach for it. Steal what fits how you work.

01

Pick your partner — warmth vs. density. design

First decision before you type anything: who's the better fit for this screen? After enough side-by-sides, the split is consistent enough to plan around. Claude reaches for warmth — off-white paper, generous padding, editorial type, a real type scale. Gemini reaches for density — data-forward, compact, tables and panels that pack a lot in a small box. Neither is "better." They're tuned for different jobs.

Claude leans

  • Editorial — type as the design, breathing room
  • Warm — off-white grounds, soft shadows, oklch color
  • Opinionated — picks a hierarchy and commits
  • Best for: landing pages, articles, portfolios, brand surfaces

Gemini leans

  • Structural — grids, panels, multi-column dashboards
  • Dense — fits more per screen, table-friendly
  • Literal — does what you said, fewer surprises
  • Best for: dashboards, admin tools, data UIs, internal apps

if you can't decide, start in Claude for taste, then port the structure to Gemini if it gets data-heavy.

02

Prompt the design, not the feature. prompt

The single biggest jump in quality came when I stopped describing what the page does and started describing how it should feel. "Build a pricing page" gets you the house style. The same request with three feel-words and one reference gets you something with a point of view. Treat the prompt like a creative brief, not a ticket.

the wish (don't)

Build a pricing page with three tiers and a FAQ.

the brief (do)

Build a pricing page, three tiers. Feel: calm, editorial, premium — think a print magazine, not a SaaS dashboard. Off-white background, one accent color, lots of negative space, a real type scale with a serif display face. Left-align everything; no centered hero. The middle tier is the hero — make it obviously the choice without a loud "POPULAR" badge.

Five extra sentences. Completely different output. The model had the ability the whole time — I just wasn't telling it which direction to point the ability.

try it ↳
Take any UI you've prompted before and re-run it with three feel-words (calm, editorial, premium) and one reference ("like a print magazine") bolted on. Watch the floor jump.
03

Artifacts as a live canvas — iterate in the panel. canvas

The Artifact panel is the design surface, not a preview. The page renders on the right while you talk on the left, and every follow-up edits the same file instead of starting over. That's the actual loop: don't re-prompt the whole thing, nudge one thing at a time and watch it land. Diary-style. Small steps, visible each step.

the iteration loop 
# 1. first pass — get the bones on screen
› pricing page, 3 tiers, editorial + warm, left-aligned

# 2. then nudge, one knob per turn — it edits in place
› tighten the vertical rhythm, ~30% less padding between rows
› middle tier: warmer card bg, the others stay flat
› bump the price numbers two steps up the type scale
› the accent is too candy — desaturate it one notch

# each line lands in seconds. no re-render from zero.

The mistake I made early was treating a near-miss as a failure and re-prompting the whole page. Don't. A near-miss is 90% done — name the 10% and let it patch. You keep all the good decisions and only move the one that's off.

04

The five design knobs — the words that actually move it. design

You don't need a design degree, you need five dials and the phrase that turns each one. These are the levers I reach for in basically every session. Say the phrase, the model moves the dial in a predictable direction. That predictability is the whole game.

Density
"tighten the rhythm" / "more breathing room"
Controls padding + line-height + gap together. The fastest fix for "feels generated."
Type scale
"more dramatic scale" / "bigger jump h1→body"
Widens the ratio between sizes. Flat scale reads cheap; dramatic scale reads designed.
Color temp
"warmer paper" / "desaturate the accent one notch"
Pulls off pure-white and pure-saturation. Warmth is what makes Claude output feel human.
Alignment
"left-align everything, no centered hero"
Centered-everything is the #1 AI tell. Editorial layouts anchor left.
Depth
"flatten the shadows" / "softer, lower elevation"
Heavy drop-shadows scream template. Soft, low shadows read intentional.

memorize these five phrases and you can re-direct any AI layout without touching a line of CSS.

05

Kill the AI tells. design

Generated UI has a tell, the same way generated prose has "delve." Once you can name the tells, you can ask for them out before they ship. Here are the ones I catch most often, and the one-line fix for each.

Purple-to-blue gradient on the hero
Fix: "one flat accent color, no gradients" — or name a real palette
Everything centered, max-width 600, dead middle
Fix: "left-align, asymmetric layout, let content set the width"
Emoji in every heading 🚀 ✨ 🎯
Fix: "no emoji; use type weight + size for emphasis instead"
System font stack, flat type scale
Fix: name two fonts — a display face + a body face — and a scale ratio
Three identical cards with a heavy drop-shadow
Fix: "vary the cards; soft shadows; one card is the hero, not all three"
"Lorem ipsum" energy — generic copy in real slots
Fix: hand it the real copy; bad copy makes good layout look bad
heads up ↳
You can fold all of these into one reusable line at the top of a prompt: "avoid the generated look — no purple gradients, no centered hero, no emoji headers, name real fonts, soft shadows." I keep it as a saved snippet and paste it into every design session.
06

Let type carry the layout. design

Claude's real strength is typography, so lean on it. Half of what reads as "designed" is just a confident type system: one display face, one body face, and a scale with real jumps between steps. When you're stuck, the fix is usually more contrast in the type, not more decoration around it.

a type brief that lands 
# name the faces — don't leave it to the system stack
Display: a tight, modern sans — Geist or Inter Tight, weight 700–800
Body:    Inter, weight 400, line-height ~1.6
Accent:  a handwritten face for margin notes — Caveat

# name the scale — flat scales read cheap
h1 clamp(2.2rem → 4rem)   // big, confident
h2 ~1.6rem
body ~1.05rem
# the JUMP from h1 to body is the design. make it dramatic.

One more: ask for text-wrap: balance on headings and text-wrap: pretty on paragraphs. Tiny CSS, but it's the difference between "typeset" and "dumped into a div." Claude knows these — you just have to ask.

07

Warmth is a recipe, not a vibe. design

"Make it warmer" works, but you get more control if you know what warmth is actually made of. It's four ingredients, and you can dial each. This is the recipe I hand the model when I want the page to feel human instead of clinical.

the warmth recipe 
// 1. never pure white — ground it in oklch, a hair of hue
--paper: oklch(0.985 0.012 85);  // off-white, warm

// 2. never pure black text — soften the ink
--ink:   oklch(0.20 0.01 60);

// 3. soft, low shadows — not heavy drop-shadows
box-shadow: 0 12px 28px -20px oklch(0.4 0.06 80 / 0.4);

// 4. one accent, desaturated a notch from "candy"
--accent: oklch(0.49 0.19 264);

The oklch part matters more than it looks. Off-white and soft-black give the whole page a temperature; pure #fff on pure #000 is the clinical default that makes generated UI feel cold. I ask for oklch by name now — the model is fluent in it.

try it ↳
On your next artifact, add one line: "use oklch color, off-white paper, soft-black ink, no pure white or pure black anywhere." It's the cheapest warmth upgrade there is.
08

Ask for the grid out loud. design

Left to itself, a model stacks everything in one column — safe, boring, and the reason a lot of AI pages feel flat. If you want structure, say the structure. Name the columns, name the asymmetry, name what spans full-width. This is where you borrow Gemini's instinct even while building in Claude.

naming the grid

Layout: a 12-column grid. The intro is two columns — copy on the left at 7 cols, a sticky table-of-contents card on the right at 5, rotated a hair off-axis like it's taped on. Below that, content returns to a single 8-column measure, left-anchored. Section dividers span full bleed. Asymmetric, not centered.

The phrase "asymmetric, not centered" does a lot of work on its own. Centered symmetry is the safe default; asymmetry with a clear anchor is what editorial design actually does. You're giving the model permission to be less safe.

09

The PageConfig move — structure first, style second. prompt

For anything with repeating parts — a feature grid, a changelog, a team page — describe the content as data first, then ask for the styling pass. You hand over a JSON-ish config, the model maps it to a layout, and you've cleanly split "what's on the page" from "how it looks." Change the data without touching the design; restyle without touching the data.

config → layout 
// step 1: hand it the shape
const page = {
  hero: { title: "Designed, not generated", accent: "generated" },
  features: [
    { name: "Density knob", blurb: "padding + rhythm in one phrase" },
    { name: "Type scale",  blurb: "dramatic jumps read designed" },
    { name: "Warmth recipe", blurb: "oklch, off-white, soft shadows" },
  ],
}

// step 2: the ask
› render this config as an editorial feature grid —
   left-anchored, warm, dramatic type scale. style only,
   keep the data exactly as given.

This is the trick frontend folks use to get clean, repeatable layouts out of a model: the config is the contract. It also makes a second pass trivial — "same data, now as a vertical timeline" reuses everything you already wrote.

10

Iterate by screenshot — the diary-style pass. canvas

The fastest design feedback loop isn't words — it's a picture. When something's off but I can't name it, I screenshot the artifact, paste it back, and point at the part. The model reads its own output as an image and fixes what it sees. This closes the gap between "I know it's wrong" and "I know the word for what's wrong."

screenshot → critique → patch 
# paste the screenshot, then point
› [screenshot] the hero feels top-heavy and the cards
   are fighting the headline for attention. calm it down.

# or ask it to critique its own work first
› [screenshot] critique this like a design lead —
   three things that read as "generated," then fix them.

The self-critique prompt is the sleeper. Asking the model to name its own AI tells before fixing them gets better results than asking for the fix directly — it has to diagnose before it patches, same as a person would. Diary-style design: shoot it, mark it up, run it back.

try it ↳
Next time an artifact is almost right, don't describe the problem — screenshot it and say "critique this like a design lead, then fix the top three." The diagnosis it writes is half the value.
11

Light by default, dark on purpose. design

Dark mode is the reflexive "make it look cool" move, and it's usually the wrong reflex for the kind of work that needs to read as crafted. Light, warm, editorial surfaces feel premium and considered; dark surfaces feel like a dev tool. Both are right sometimes — just pick on purpose, not by default.

Reach for light when

  • It's a brand or marketing surface
  • The content is long-form / editorial
  • You want warmth and trust
  • It'll be printed or screenshotted for a portfolio

Reach for dark when

  • It's a tool, dashboard, or code surface
  • There's media or charts that pop on dark
  • It runs at night / long sessions
  • The mood is technical, focused, heads-down

a single dark terminal block on a light page gives you the "cool" hit without going full dark mode. best of both.

12

Lift it out of the panel — the last mile is short now. workflow

The artifact isn't the destination, it's the design comp that happens to run. Once it looks right, get it into a real project. For a self-contained HTML artifact that's a copy-paste; for a React one it's a component and its tokens. The model that designed it can also do the port — ask.

artifact → repo 
# ask for the port explicitly — don't hand-translate
› extract the color + type tokens into a :root block
   I can drop into my design system. keep the oklch values.

› split this into a Next.js component + a tokens file.
   Tailwind v4, no inline styles, mobile-first.

# then it's a normal commit
$ git add . && git commit -m "feat: pricing page from artifact"

The thing that changed isn't that the model can design — it's that the distance from "looks right in the panel" to "lives in the repo" collapsed to a couple of prompts. The bottleneck moved all the way back up to taste and direction. Which is exactly where you want it.
