The token trap — feed the model less, get a better build.

The instinct when an AI gets something wrong is to give it more — paste the whole file, the whole page, the whole codebase. That's the trap. More context isn't more signal; it's more noise to wade through. This entry is about the opposite move: serialize a page down to the 3,000 tokens that actually matter, and watch the model nail the rebuild on the first try.

—Lupo · The Mess is the Method

Here's the lesson that took me the longest to actually believe: a context window is a budget, not a bucket. When I copied document.body.outerHTML off a real marketing site and dropped it into Claude, I handed it fifty thousand tokens of base64 images, tracking scripts, hidden SVGs, and ten layers of <div> soup — and then wondered why the rebuild came back generic.

The model wasn't being lazy. It was doing pattern-matching across a haystack I built for it. The fix isn't a better prompt. It's a better payload. Strip the page down to its skeleton first, and the same model — same prompt — gives you something you can actually use.

Below: the three browser snippets I keep on a hotkey for exactly this. Each one runs in the DevTools console, copies a clean payload to your clipboard, and tells you what to say once you paste. No install, no API key, works on any page you can open.

01

Name the trap before you fall in it. mindset

Quick gut-check before any of the snippets matter. When you paste something into an AI to get help, ask: what fraction of this is the model actually going to use? If you're pasting a 700-line config to fix one block, or a whole page's HTML to rebuild one section, the answer is "almost none" — and the rest is actively working against you.

Three failure modes I kept hitting, all the same root cause:

buried signal
The fix is in there, but so is 20× its weight in noise. The model averages it out.
blown budget
Half the window is gone before the real question. Less room to actually reason.
generic out
Vague in, vague out. A wall of div soup reads as "anything," so you get anything.

a context window is a budget, not a bucket. spend it on signal.

02

The topography map — !ai-page-map. console snippet

Start with the lightest one. This ignores all text, colors, and detail and walks the page top to bottom, emitting a clean markdown tree of just the macro-layout — headers, mains, sections, navs, footers, and the major container divs. It's perfect when your question is structural: "why is my sticky sidebar scrolling away?"

console — !ai-page-map 
(function mapPageTopography() {
  function getStructure(node, depth = 0) {
    if (depth > 6) return ''; // don't recurse forever
    let out = '';
    Array.from(node.children).forEach(child => {
      const tag = child.tagName.toLowerCase();
      const id  = child.id ? `#${child.id}` : '';
      // keep semantic tags + major structural divs only
      if (['header','main','footer','section','nav','aside','form'].includes(tag)
          || (tag === 'div' && (child.id || child.className.includes('container')))) {
        out += `${'  '.repeat(depth)}- <${tag}${id}>\n`;
        out += getStructure(child, depth + 1);
      } else if (child.children.length) {
        out += getStructure(child, depth); // skip wrapper, keep digging
      }
    });
    return out;
  }
  copy(`### Page Topography\n${getStructure(document.body)}`);
  console.log("🗺️ topography copied");
})();
then paste & say "Here's my page topography. I'm trying to make the sidebar sticky but it scrolls with the page — which container is breaking the sticky context?"
try it ↳
Open any site you like, hit F12, paste the snippet into the Console tab, press Enter. The tree is already on your clipboard. Paste it into a fresh chat — notice how readable a whole page just became.
03

The interactive surface — !ai-surface. console snippet

Different question, different cut. When you don't care about layout but you care about what's clickable — every button, link, input, and form, what it says and where it points — this is the one. It's the payload for writing tests, mapping a flow, or pointing a browser agent at a page.

console — !ai-surface 
(function extractActionSurface() {
  const actions = [];
  document.querySelectorAll('a, button, input, select, textarea').forEach(el => {
    if (el.offsetWidth === 0 && el.offsetHeight === 0) return; // skip hidden
    const tag    = el.tagName.toLowerCase();
    const type   = el.type ? ` [type="${el.type}"]` : '';
    const text   = (el.innerText || el.placeholder || el.ariaLabel || 'No label')
                     .trim().replace(/\n/g, ' ').substring(0, 60);
    const target = el.href ? ` -> ${el.href.replace(location.origin, '')}` : '';
    actions.push(`- ${tag}${type}: "${text}"${target}`);
  });
  copy(`### Interactive Surface\n\n${actions.join('\n')}`);
  console.log("🕹️ surface copied");
})();
then paste & say "Here's the interactive surface of my page. Write a Playwright test that fills the contact form and asserts the submit button is enabled."

Notice the pattern across both snippets: one job each. Layout, or actions — never both at once. That's the whole discipline. You decide what the model needs before you hand it anything.

04

The big one — !ai-dom-lite, the 94% compressor. console snippet

When you genuinely need the full structure — rebuild this whole landing page in React — this is the snippet that makes it possible without torching your budget. It clones the body, deletes everything heavy and non-structural (scripts, SVGs, iframes, canvases), strips every noisy attribute down to the handful that matter for layout, and truncates long paragraphs. Fifty thousand tokens become about three thousand.

console — !ai-dom-lite 
(function exportCleanDOM() {
  const clone = document.body.cloneNode(true);

  // 1. nuke the heavy, non-structural elements
  clone.querySelectorAll('script, style, svg, path, iframe, canvas, video')
       .forEach(el => el.remove());

  // 2. strip noisy attributes + truncate long text
  const walker = document.createTreeWalker(clone, NodeFilter.SHOW_ELEMENT);
  let node;
  while (node = walker.nextNode()) {
    Array.from(node.attributes).forEach(attr => {
      // keep only the essentials for layout/styling
      if (!['id','class','href','src','alt','type','name'].includes(attr.name))
        node.removeAttribute(attr.name);
    });
    Array.from(node.childNodes).forEach(child => {
      if (child.nodeType === Node.TEXT_NODE) {
        const t = child.nodeValue.trim();
        if (t.length > 80) child.nodeValue = t.substring(0,80) + '... [truncated]';
      }
    });
  }
  copy(`### Token-Optimized DOM\n\`\`\`html\n${clone.innerHTML}\n\`\`\``);
  console.log("🧹 minimized DOM copied");
})();
then paste & say "Rebuild this entire page layout using React Server Components and Tailwind v4. Match the structure; I'll handle the copy."
heads up ↳
!ai-dom-lite keeps class names, so it's gold for Tailwind-built sites — the classes are the design. On a site using obfuscated/hashed class names you'll get structure but not styling intent; pair it with !ai-theme (next) to recover the colors and fonts.
05

The combo move — theme + structure in two pastes. workflow

Here's how the snippets compound. To get an AI to convincingly rebuild a live page, it needs two things: the brand (colors, fonts) and the bones (structure). Run two snippets, paste two clean payloads, and you've handed over a near-complete design brief for a fraction of the tokens a screenshot-plus-HTML dump would cost.

console — !ai-theme (run first, nothing selected) 
(function designSystemExtractor() {
  const colors = new Set(), fonts = new Set();
  document.querySelectorAll('body *').forEach(el => {
    const s = getComputedStyle(el);
    if (s.color !== 'rgba(0, 0, 0, 0)') colors.add(s.color);
    if (s.backgroundColor !== 'rgba(0, 0, 0, 0)') colors.add(s.backgroundColor);
    if (s.fontFamily) fonts.add(s.fontFamily.split(',')[0].replace(/"/g, ''));
  });
  copy(`### Design System\nColors:\n${[...colors].join('\n')}\nFonts:\n${[...fonts].join('\n')}`);
})();

The two-step recipe, start to finish:

the flow 
# 1. grab the brand → clipboard, paste into a doc/chat
▸ run !ai-theme      → colors + fonts

# 2. grab the bones → clipboard, paste below it
▸ run !ai-dom-lite   → structure, ~3k tokens

# 3. one prompt, both payloads in context
▸ "Rebuild this page. Use the color + font tokens above
   and match the DOM structure below. Tailwind v4, mobile-first."

two clean pastes beat one giant screenshot. every single time.

06

The principle that outlives the snippets. mindset

The console tricks are handy, but they're just one instance of a rule that shows up everywhere I work with models. A bloated CLAUDE.md that loads 700 lines every session when the target is under 200. A whole repo pasted in to fix one function. A meeting transcript handed over raw instead of summarized. Same trap, different surface.

The move is always the same: decide what the model needs, build the smallest payload that carries it, then ask. You're not dumbing things down — you're doing the editorial pass before the model has to. That pass is the part you're actually good at, and it's the part that makes the difference between a generic answer and a sharp one.

try it ↳
Next time you're about to paste a big blob into an AI, stop and ask "what here is signal?" Delete the rest before you hit send. That one habit — not any single snippet — is the whole lesson.
