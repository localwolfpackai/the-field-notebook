Same prompt, two souls — how Claude and Gemini design the very same screen differently.

Type one identical prompt into Claude and Gemini and you don't get one app twice — you get two. One comes back warm, roomy, editorial; the other comes back dense, gridded, data-first. Neither is wrong. Ten moves to read the split, learn the words each model actually responds to, and steer either one to your taste.

I ran an experiment that should be boring and isn't: I pasted the exact same prompt — "build me a dashboard for a coffee subscription business" — into Claude and into Gemini, changed nothing, and put the two results next to each other. They didn't look like two versions of one idea. They looked like two designers with different temperaments solving the same brief.

Claude gave me air. Big editorial headline, one metric per row, serif numerals you could read across the room, a palette that felt like a print magazine. Gemini gave me a cockpit. A tight grid of stat tiles, deltas in green, monospace everywhere, six numbers where Claude showed three. Claude wants you to feel the data; Gemini wants you to scan it.

That difference is a tool, not a verdict. Once you can name the split — warmth vs. density — you stop fighting whichever model you're in and start steering it. Ten moves below, each with the trait, a real prompt phrase, and a try-it. 01

Run the same prompt twice — the cheapest design study you'll ever do. design

Before you theorize about which model is "better at design," do the experiment. Open Claude (Artifacts) and Gemini (Canvas) side by side, paste the identical prompt into both, and change nothing. The point isn't to crown a winner — it's to see, in your own brief, how each model fills the gaps you left open. Every prompt has a thousand unstated decisions; the model's defaults are its personality, and this is how you meet it.

prompt.txt — paste the same thing into both, verbatim
# The control prompt. No design adjectives on purpose —
# we want each model's *default* taste, not ours yet.
Build a dashboard for a coffee subscription business.
Show this month's revenue, active subscribers, and churn.
Make it look good.
try it
Run it now with your product. Screenshot both. Put them side by side in a slide. The gap between the two screenshots is the entire lesson — and it's worth more than any blog post (this one included) telling you what the gap "should" be.
02

Name the split — almost every difference rolls up to warmth vs. density. read

Once you've stared at a few side-by-sides, a single axis explains most of what you see. Claude defaults toward warmth: generous whitespace, fewer elements per screen, editorial type, a human tone. Gemini defaults toward density: tight grids, more data visible at once, functional type, a tool-like tone. Same brief, opposite ends of one dial.

TraitClaude leans…Gemini leans…
Whitespacegenerous, roomytight, efficient
Info per screenfew, focusedmany, scannable
Type voiceeditorial / serif accentsfunctional / mono
Default mooda magazinea cockpit
Reads asmade by a personbuilt by a system

neither end is "correct." a hospital monitor wants density. a landing page wants warmth.

03

Read the padding first — spacing is the loudest tell of all. read

If you only learn to read one signal, make it spacing. Claude reaches for big, consistent padding and large gaps between elements — the layout feels like it can exhale. Gemini compresses: smaller padding, tighter gaps, more packed into the same viewport. You can spot which model made a screen from across the room, before you read a single word, just by how much air is in it.

Claude · roomy

Defaults to large padding tokens and wide gaps. One idea per region. The layout breathes; nothing is fighting for space.

  • ~24–32px section padding
  • one metric per row, lots of gutter
  • generous line-height on body copy

Gemini · packed

Defaults to compact padding and tight gaps. Multiple ideas per region. Maximizes information density, minimizes scroll.

  • ~8–12px tile padding
  • 2–3 column stat grids
  • tighter line-height, smaller text
heads up
Don't mistake "more air" for "better." Claude's roominess can waste a power-user's screen; Gemini's density can overwhelm a casual one. The right spacing is the one your user's task wants — that's the call only you can make.
04

Read the type — serif editorial vs. monospace data. read

The second tell is typography. Claude likes to introduce contrast — a serif or a heavier display weight for headlines, set big, treated like a magazine masthead. It uses type to create hierarchy you feel. Gemini stays functional and even: clean sans throughout, monospace for numbers, smaller sizes that let more fit. One designs a cover; the other designs a readout.

Claude's type instincts
serif headline display size high contrast editorial balanced wrap
Gemini's type instincts
sans throughout mono numerals smaller sizes even hierarchy functional

watch the *numbers*. claude sets a big revenue figure like a hero. gemini sets it in mono, in a tile.

05

Read the color — earthy warmth vs. signal blue. read

Palette is the third giveaway, and it tracks the same axis. Claude tends toward warmer, earthier defaults — clays, creams, muted accents that feel hand-picked. Gemini tends toward cooler, brighter, signal-style color — blues, greens-for-up, reds-for-down, the language of a status board. Claude colors a brand; Gemini colors a system where color carries meaning.

defaults.css — the palettes they reach for unprompted
/* Claude's instinct — warm, editorial, brand-led */
--bg:     oklch(0.98 0.01 80);   /* warm paper */
--accent: oklch(0.63 0.13 47);   /* clay / terracotta */
--text:   oklch(0.20 0.01 60);   /* warm near-black */

/* Gemini's instinct — cool, functional, signal-led */
--bg:     oklch(0.99 0.00 0);    /* clean white */
--accent: oklch(0.55 0.16 264);  /* google blue */
--up:     oklch(0.62 0.16 145);  /* green delta */
--down:   oklch(0.58 0.18 25);   /* red delta */
try it
Sample the hexes out of both screenshots with any color picker and drop them on a row. You'll see the temperature split — warm hues clustering on Claude's side, cool on Gemini's. It's the fastest way to make the difference undeniable to a skeptical teammate.
06

Steer Claude toward data — ask for density in its own language. steer

Claude's warmth is a default, not a ceiling. When you genuinely need a packed, information-dense view, you have to ask — and ask in spatial, concrete words, because vague requests just get you more warmth. Name the grid, name the count, name the compactness. Claude will happily build a cockpit; it just won't volunteer one.

steer-claude.txt — words that pull it toward density
# Append to your prompt when you want Gemini-style packing:
Make this information-dense — a power-user dashboard, not a landing page.
Use a compact 3-column grid of stat tiles, tight padding.
Show deltas (▲ / ▼ vs last month) on every metric.
Numbers in monospace. Minimize whitespace. No big hero.
heads up
"Make it denser" alone rarely works — it's too abstract. The phrases that land are spatial and countable: "3-column grid," "tight padding," "show deltas," "no hero." Give the model the layout decision, not the vibe.
07

Steer Gemini toward warmth — ask for soul in its own language. steer

The reverse holds. Gemini can absolutely produce a warm, editorial, breathing layout — you just have to counter its density default explicitly. Ask for the air, the serif, the brand palette, the one-thing-per-screen focus. The trick is the same as steering Claude: don't say "make it prettier," say exactly which knob to turn.

steer-gemini.txt — words that pull it toward warmth
# Append to your prompt when you want Claude-style soul:
Make this editorial and spacious — a brand page, not a control panel.
Generous whitespace; one focal metric, set large like a headline.
A serif display font for headings, warm earthy palette.
Fewer elements. Let it breathe. Optimize for feel, not count.
try it
Run Move 06 and Move 07 back to back on the same model. Watch one model produce both souls on command. That's the real lesson: the personality is a starting point you can override, not a wall — once you know the words.
08

Hand both a token spec — the surest way to erase the house style. design

Prompts steer; tokens decide. The most reliable way to get matching output from two different models is to stop describing taste in prose and start handing over the actual values — your spacing scale, your type, your palette. Give both models the same tokens.css and tell them to use only those, and the warmth-vs-density gap mostly collapses. They diverge in the gaps you leave; close the gaps. (This is exactly the move from Vol. 11.)

tokens.css — the same brief, in numbers both models obey
/* Paste this into BOTH, then: "Use ONLY these tokens. No others." */
:root {
  --space-1: 8px;  --space-2: 16px;  --space-3: 24px;
  --font-display: 'Geist', serif;
  --font-body:    'Inter', sans-serif;
  --accent: oklch(0.49 0.19 264);
  --radius: 12px;
}

prompts argue with the model's taste. tokens replace it. when consistency matters, ship the tokens.

09

Pick the model for the job — the default soul is a feature when it fits. read

Here's the practical payoff: when you don't want to fight defaults, just start with the model whose soul already matches the job. Marketing page, brand site, anything that needs to feel human on first glance? Start in Claude — you're rowing with the current. Internal admin panel, analytics view, anything where users scan dozens of numbers fast? Start in Gemini. You can always steer, but starting aligned is free.

10

Steal from both — the best output is usually a remix of the two souls. steer

The endgame isn't picking a team. It's running both, then cherry-picking. Take Claude's editorial headline and spacing, take Gemini's delta tiles and scannable grid, and tell either model to combine them. "Claude's warmth on the hero, Gemini's density in the stats" is a real, buildable instruction once you can name the parts. The models gave you two strong drafts for the price of one prompt — your taste is the editor that fuses them.

remix.txt — name the part you want from each soul
# Feed either model the combined brief once you've seen both:
Keep the layout warm and editorial up top — a large serif
headline and one hero metric with generous whitespace (Claude's instinct).
Below the fold, switch to a dense delta grid — compact
stat tiles with ▲/▼ changes, monospace numbers (Gemini's instinct).
# One screen, both souls, on purpose.
try it
This is the whole notebook's thesis in one move: the model is a fast draft engine, and you are the director. Two souls, one editor. Run both, name what you love in each, and ask for the fusion. That output beats either default — because it has your taste in it.
