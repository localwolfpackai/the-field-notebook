The texture layer — seven CSS moves that make an AI artifact stop looking generated.

The model nails the layout. It nails the spacing, the grid, the type scale. What it almost never reaches for is texture — the feathered blur, the 1px specular border, the edge that fades instead of cuts. That last 5% is the whole tell. This notebook is the seven paste-in effects that close it, every one lifted from my own snippets/ui-effects drawer.

—Lupo · The Mess is the Method
Read · ~12 min Surface · any HTML artifact Assumes · you've shipped one AI-built page Voice · open-notebook, casual

Here's the pattern I kept hitting. I'd ask Claude or Gemini for a landing page, and the structure would come back genuinely good — clean hierarchy, sane padding, a real grid. Then I'd put it next to something off Apple's site and feel the gap instantly without being able to name it.

The gap is texture. Models reach for structure because structure is describable in language — "two columns, card grid, sticky header." Texture lives below language. It's the way a blur ramps instead of slams, the way light catches a 1px edge, the way a list fades at the rail instead of ending in a hard scrollbar. Nobody prompts for that because nobody has the words for it.

So I stopped prompting for it. I keep a drawer of seven effects and paste them in after the model gets the bones right. Each one is a named class, a copy-paste block, and a knob or two. This is that drawer — with the demos running live right here on the page so you can see the before/after without opening a thing.

01

Progressive blur — the fade that feathers instead of slamming. css

The single biggest "this looks designed" upgrade, and the one models never reach for. A plain backdrop-filter: blur(20px) gives you a hard line where sharp content meets blur. iOS doesn't do that — it ramps the blur across a gradient so content recedes into fog. You get there by stacking layers, each with a heavier blur and a mask that only shows its own slice.

See how the chips dissolve into the footer instead of getting chopped by a line? That's eight stacked layers from blur(0.5px) up to blur(64px), each masked to a 12.5% band. Here's the shape — just the top three layers; the pattern repeats:

progressive-blur-bottom.css 
/* fixed sheet at the bottom — drop in <body> */
.gradient-blur { position: fixed; inset: auto 0 0 0; height: 65%;
                 z-index: 5; pointer-events: none; }

.gradient-blur::before {           /* layer 1, lightest */
  backdrop-filter: blur(0.5px);
  mask: linear-gradient(to bottom,
    rgba(0,0,0,0) 0%,    rgba(0,0,0,1) 12.5%,
    rgba(0,0,0,1) 25%,   rgba(0,0,0,0) 37.5%); }

.gradient-blur > div:nth-of-type(1) {
  backdrop-filter: blur(1px);  /* each layer: 2× blur, */
  mask: linear-gradient(to bottom, /* band shifted down 12.5% */
    rgba(0,0,0,0) 12.5%, rgba(0,0,0,1) 25%,
    rgba(0,0,0,1) 37.5%, rgba(0,0,0,0) 50%); }

/* ...repeat for blur(2,4,8,16,32,64px). 8 layers total. */
try it ↳
Want it at the top instead (sticky header)? Flip every to bottom to to top and set inset: 0 0 auto 0. Same six <div>s. That's the whole change.
02

Gradient border — the 1px specular edge Apple uses everywhere. css

Solid borders read as "web." Real products use a hairline that looks like light catching the edge of a physical object — brighter on one side, fading to nothing on the other. The trick is a 1px ::before with a diagonal gradient, clipped to a ring with mask-composite so only the border shows.

Look at the top-left of each card — that faint bright edge isn't a shadow, it's a masked gradient. On a dark surface it makes a card look milled out of aluminum. Here's the entire snippet:

border-gradient.css 
/* add class "border-gradient" to any element, */
/* then REMOVE its existing border. */
.border-gradient { position: relative; }

.border-gradient::before {
  content: ""; position: absolute; inset: 0;
  border-radius: 10px;
  padding: 1px;                 /* the border thickness */
  /* two masks + exclude = only the 1px ring shows */
  -webkit-mask: linear-gradient(#fff 0 0) content-box,
               linear-gradient(#fff 0 0);
  -webkit-mask-composite: xor;
          mask-composite: exclude;
  background: linear-gradient(225deg,
    rgba(255,255,255,0)   0%,    /* light from top-left */
    rgba(255,255,255,.2)  50%,
    rgba(255,255,255,0) 100%);
  pointer-events: none;
}

the knob here is 225deg. that's where your light source is. match it to your shadows.

03

Edge masks — let content fade, not cut. inline

The cheapest effect in the drawer and one of the highest-leverage. Any time content runs off the edge of a container — a horizontal carousel, a long sidebar, a logo strip — a hard cutoff screams "scrollable region." Fading the edges to transparent signals "there's more" without an ugly scrollbar. It's two lines of inline CSS, no wrapper needed.

The swatches dissolve at both rails instead of hitting a wall. That's a single mask-image on the scroll container:

alpha-mask · inline on any element 
/* horizontal — fade left + right rails */
mask-image: linear-gradient(to right,
  transparent, black 15%, black 85%, transparent);
-webkit-mask-image: linear-gradient(to right,
  transparent, black 15%, black 85%, transparent);

/* vertical — same idea, top + bottom */
mask-image: linear-gradient(to bottom,
  transparent, black 15%, black 85%, transparent);
heads up ↳
Always ship both mask-image and -webkit-mask-image. Safari and a lot of in-app browsers still need the prefixed one, and without it the effect silently does nothing.
04

Scroll-in float — content focuses into place. js

Apple landing pages almost never dump everything at once. Sections float up and sharpen as you reach them — opacity, a small translateY, and a blur clearing to zero, all at once. It reads as "premium weight": the content gets developed onto the screen rather than just appearing. One keyframe plus a tiny IntersectionObserver so it only fires when you actually scroll there.

live · these floated in on view
Row one. Faded up, slid 22px, blur cleared to zero.
Row two. Same transition — the eye reads it as focus.
Row three. Staggered by 90ms so it cascades, not snaps.

The keyframe is the whole aesthetic; the observer is just the trigger. Here's both:

animation-keyframe.css + observer.js 
/* the move: fade + rise + focus */
@keyframes animationIn {
  0%   { opacity: 0; transform: translateY(30px); filter: blur(8px); }
  100% { opacity: 1; transform: translateY(0);    filter: blur(0); }
}
/* class: [animation:animationIn_0.8s_ease-out_both] animate-on-scroll */

// only run it when the element scrolls into view
const io = new IntersectionObserver((entries) => {
  entries.forEach((e) => {
    if (e.isIntersecting) {
      e.target.classList.add("animate");
      io.unobserve(e.target);   // fire once, then stop
    }
  });
}, { threshold: 0.2, rootMargin: "0px 0px -10% 0px" });

document.querySelectorAll(".animate-on-scroll").forEach((el) => io.observe(el));
try it ↳
Stagger it: give each item animation-delay: calc(var(--i) * 90ms) and set --i per element. Now the section cascades in instead of firing all at once. The demo above does exactly this.
05

Noise overlay — the cure for flat plastic. advanced

Pure flat fills are the most reliable AI-slop tell. Real surfaces have grain. A faint field of noise blended over a solid color is what turns "default Tailwind card" into "frosted glass with a matte finish." You can do a quick version with a tiling PNG, but the snippet in my drawer generates it on a <canvas> and blends it through an SVG filter, so it scales to any element size without a texture asset.

noise — the quick + the real version 
/* QUICK: one tiling SVG noise, blended at low opacity */
.grain::after {
  content: ""; position: absolute; inset: 0;
  background: url("data:image/svg+xml,...feTurbulence...");
  opacity: 0.04;          /* the knob — 0.03–0.06 is plenty */
  mix-blend-mode: overlay;
  pointer-events: none;
}

/* REAL (from the drawer): canvas-generated, SVG-blended */
/* registered as a custom filter you call in CSS: */
--fx-filter: noise(0, 1, 0.25);
/*           saturation, intensity, opacity ↑ */
/* saturation 0 = grayscale grain, 1 = chromatic */

For 90% of artifacts the ::after + feTurbulence version is all you need, and it's zero JavaScript. Reach for the canvas engine only when you want the grain to react to resize or pair with the glass effect below.

heads up ↳
Noise is a seasoning, not a sauce. Above 0.06 opacity it stops reading as texture and starts reading as a broken JPEG. When in doubt, turn it down until you're not sure it's there — that's the right amount.
06

Liquid glass — actual refraction, not just blur. advanced

This is the deep end, and the one I reserve for a hero element — one card, one nav bar, not the whole page. Standard backdrop-filter: blur() just smears what's behind. Real glass bends light at its edges. The drawer's FxFilter engine draws a displacement map on a canvas, feeds it to an SVG <feDisplacementMap>, and warps the backdrop the way a thick pane of glass actually would — chromatic aberration on the edges and all.

liquid-glass — how you call it 
// 1. paste the FxFilter engine once (it self-inits)
//    it scans for --fx-filter and injects the SVG for you

/* 2. then it's a one-line CSS property on your hero element */
.hero-card {
  --fx-filter: liquid-glass(2, 10, 0);
  /*               refraction, offset, chromatic ↑ */
  border-radius: 20px;     /* engine reads this for edge warp */
}

/* stack it with the others for the full Apple stack: */
.hero-card { --fx-filter: noise(0,1,.2) liquid-glass(2,10,1); }
/*                        chromatic on ↑ — splits R/G/B at edges */

The engine tracks each element's size and border-radius and regenerates the displacement map when they change — so it survives responsive resizing without you wiring anything up. The cost is real, though: it's a requestAnimationFrame loop scanning the DOM. Which is exactly why it's a hero-only move.

heads up ↳
Don't carpet-bomb a page with this. One refracting element is jewelry; ten is a space heater. If you need glassy-but-cheap on many elements, use plain backdrop-filter: blur() + the noise from #5 + the gradient border from #2. That combo gets you 80% of the look for 5% of the cost.
07

The prompt that asks for all of it — by name. workflow

Here's the meta-move. Once you have the vocabulary — progressive blur, specular border, edge mask, scroll-in float, noise grain — you can hand it back to the model. The reason Claude didn't reach for these isn't that it can't write them; it's that "make it look nice" doesn't name them. Name them and it builds them in on the first pass.

the texture-pass prompt 
you> The layout's right. Now do a texture pass, no layout changes:

   1. Progressive blur on the sticky footer — 6 stacked
      layers, blur(1px)→blur(32px), masked in 12.5% bands.
   2. Specular 1px gradient border on every card
      (225° light, mask-composite: exclude). No solid borders.
   3. Edge-mask the horizontal rails — fade to transparent
      at 15%/85%, ship the -webkit- prefix too.
   4. Scroll-in float on each section: opacity +
      translateY(30px→0) + blur(8px→0), IntersectionObserver.
   5. 0.04-opacity noise overlay on the hero only.

claude> Done. Texture applied, layout untouched. Notes on each ↓

That's the actual workflow: structure from the model, vocabulary from this notebook, texture pass back to the model with the effects named and their knobs set. You're not asking it to have taste. You're handing it yours, in terms it can compile.
