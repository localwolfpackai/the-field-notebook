Make the model hand you JSON — ten moves for turning a prompt into typed UI.

Prose is for humans. Your interface wants an object — a title here, a price there, a list it can .map() over. This notebook is the move that stops you from regex-ing a paragraph apart: you ask Claude or Gemini for a schema-shaped payload, validate it, and render it straight into components. One schema, one validator, one fallback. Both models, side by side.

Here's the trap I fell into on my first AI feature: I asked the model for a product card and it gave me a lovely paragraph. Warm, fluent, useless. Because a card isn't a paragraph — it's a title, a tagline, a price, and a button. I spent an hour writing string-splitting code to claw those fields back out of the prose, and it broke the moment the model phrased things differently.

The fix isn't more clever parsing. It's asking the model to never produce prose in the first place. Modern models will hand you a typed object that matches a schema you define — Claude through a tool/JSON instruction, Gemini through responseSchema. You stop reading the answer and start mapping it.

Below: each move gets a number, a one-line claim, the actual code, and a try-it crumb. The panel under this intro is real — hit the button and watch the same JSON on the left become the card on the right. That's the whole job: object in, component out.

01

Stop parsing prose — the cheapest reliability win is asking for the object, not the answer. model

The instinct is to ask "describe a product card for running shoes" and then pull the pieces out of whatever comes back. Don't. Every sentence the model writes is a sentence you have to reverse-engineer, and it'll phrase it differently on every call. You're building a parser for free-form English, which is a research project, not a feature.

Flip it. Tell the model: return only a JSON object with these exact keys. Now the output isn't language you interpret — it's data you consume. The model is doing the hard part (deciding the values); you're doing the easy part (rendering known fields). That handoff is the entire move.

heads up
The words for this differ per vendor — structured outputs, JSON mode, tool use, function calling, responseSchema. They're the same idea wearing four hats: you hand the model a shape, it fills it in.
02

Write the schema first — it's not boilerplate, it's the spec for the whole feature. design

Before you touch the prompt, write down the exact shape you want back. This is the most important five minutes of the build, because the schema is simultaneously the prompt's instruction, the validator's rulebook, and the UI's prop types. Get it right once and three layers fall into place.

schema.ts — the single source of truth
// One shape. The prompt obeys it, the validator enforces it,
// the component reads it. Define it once, here.
type ProductCard = {
  title: string;        // "Trailblazer GTX"
  tagline: string;      // one line, < 60 chars
  priceUsd: number;     // 139, not "$139.00"
  badge: "new" | "sale" | "none";  // an enum, not free text
  rating: number;       // 0–5
  reviews: number;
  ctaLabel: string;     // "Add to bag"
};
try it
Make every field a primitive or an enum where you can. priceUsd: number beats price: string every time — the model can't sneak a currency symbol or "call for pricing" into a number.
03

Claude — use a tool as the JSON contract, so the model has to fill your shape. claude

The cleanest way to get strict JSON out of Claude is to define a tool whose input_schema is your shape, then force the model to call it. Claude doesn't write prose — it emits a tool call whose arguments are exactly your object. You read content[0].input and you're done.

route.ts — Claude, tool as schema
import Anthropic from "@anthropic-ai/sdk";
const client = new Anthropic();

const msg = await client.messages.create({
  model: "claude-sonnet-4-6",
  max_tokens: 512,
  // 1. describe the shape as a tool
  tools: [{
    name: "emit_card",
    description: "Return one product card.",
    input_schema: {
      type: "object",
      properties: {
        title:    { type: "string" },
        tagline:  { type: "string" },
        priceUsd: { type: "number" },
        badge:    { type: "string", enum: ["new","sale","none"] },
        rating:   { type: "number" },
        reviews:  { type: "number" },
        ctaLabel: { type: "string" },
      },
      required: ["title","tagline","priceUsd","badge","ctaLabel"],
    },
  }],
  // 2. force the tool — no prose escape hatch
  tool_choice: { type: "tool", name: "emit_card" },
  messages: [{ role: "user", content: "Trail running shoe, premium." }],
});

// 3. the object is right there — no parsing
const block = msg.content.find(b => b.type === "tool_use");
const card = block.input;  // { title, tagline, priceUsd, ... }

forcing the tool is the trick — without tool_choice Claude might just chat.

04

Gemini — hand it a responseSchema and turn JSON mode on. Same idea, fewer moving parts. gemini

Gemini takes the schema directly in the generation config. You set responseMimeType to JSON, pass your shape as responseSchema, and the model is constrained to emit conforming JSON as plain text — which you JSON.parse() on the way out. No tool dance; the config is the contract.

route.ts — Gemini, responseSchema
import { GoogleGenerativeAI, SchemaType } from "@google/generative-ai";
const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY);

const model = genAI.getGenerativeModel({
  model: "gemini-2.5-flash",
  generationConfig: {
    responseMimeType: "application/json",   // JSON mode on
    responseSchema: {
      type: SchemaType.OBJECT,
      properties: {
        title:    { type: SchemaType.STRING },
        tagline:  { type: SchemaType.STRING },
        priceUsd: { type: SchemaType.NUMBER },
        badge:    { type: SchemaType.STRING, enum: ["new","sale","none"] },
        rating:   { type: SchemaType.NUMBER },
        reviews:  { type: SchemaType.NUMBER },
        ctaLabel: { type: SchemaType.STRING },
      },
      required: ["title","tagline","priceUsd","badge","ctaLabel"],
    },
  },
});

const res = await model.generateContent("Trail running shoe, premium.");
const card = JSON.parse(res.response.text());  // guaranteed JSON text

Claude

Schema lives in a tool. Force it with tool_choice. Read .input — already an object, zero parsing.

Gemini

Schema lives in generationConfig. Set JSON mime type. Read .text() and JSON.parse it once.

your frontend doesn't care which one ran — it just gets a card object.

05

Validate at the door — "the model promised a schema" and "the bytes match it" are different facts. backend

Constrained decoding is good, not perfect. A field can come back as a string where you wanted a number, an enum can drift, a required key can go missing on a weird prompt. Don't let unverified data reach a component — parse it through a real validator and let that be your runtime type. Zod is the standard move: one schema gives you validation and the TypeScript type for free.

card.schema.ts — Zod is the bouncer
import { z } from "zod";

export const Card = z.object({
  title:    z.string().min(1),
  tagline:  z.string().max(80),
  priceUsd: z.number().positive(),
  badge:    z.enum(["new", "sale", "none"]),
  rating:   z.number().min(0).max(5).default(0),
  reviews:  z.number().int().nonnegative().default(0),
  ctaLabel: z.string().default("View"),
});

export type Card = z.infer<typeof Card>;  // ← your real type, derived

// at the door:
const parsed = Card.safeParse(rawFromModel);
if (!parsed.success) return fallbackCard;  // never throw into the UI
const card = parsed.data;                // typed + clean
try it
.default() on the soft fields means a missing rating renders a zero, not a crash. Validation isn't just rejection — it's where you set the floor for "good enough to show."
06

Map the object straight into UI — this is the moment the whole approach pays off. frontend

Once card is a validated, typed object, the component is boring — and boring is the goal. No conditionals guessing whether a field exists, no string surgery, no "if the model said X." You read known props. The same render function works whether Claude or Gemini produced the data, because both produced the same shape.

ProductCard.tsx — object in, JSX out
function ProductCard({ card }: { card: Card }) {
  return (
    <article className="card">
      {card.badge !== "none" && <span className={`tag ${card.badge}`}>{card.badge}</span>}
      <h3>{card.title}</h3>
      <p className="sub">{card.tagline}</p>
      <div className="stats">
        <b>${card.priceUsd}</b>
        <span>★ {card.rating} · {card.reviews} reviews</span>
      </div>
      <button>{card.ctaLabel}</button>
    </article>
  );
}

notice: zero parsing in the component. that's the whole win.

07

The fallback when JSON breaks — design the sad path before you need it. polish

A stray token, a truncated response, a model that decided to wrap your JSON in a ```json fence — it happens. The difference between a toy and a product is whether that turns into a white screen or a graceful card. Three layers, cheap to add: strip fences, try-parse, validate, and if any step fails, show a designed empty state instead of an exception.

safeCard.ts — never throw into the render tree
export function safeCard(raw: string | object): Card | null {
  try {
    // 1. some models fence JSON in ```json … ``` — strip it
    const text = typeof raw === "string"
      ? raw.replace(/^```(json)?|```$/g, "").trim()
      : null;
    const obj = text ? JSON.parse(text) : raw;

    // 2. validate — the bouncer from move 05
    const parsed = Card.safeParse(obj);
    return parsed.success ? parsed.data : null;
  } catch {
    return null;  // 3. caller renders the empty state
  }
}
heads up
A null return is a feature, not a failure. It hands the UI a clean signal — "render the placeholder" — instead of an exception three components deep. Your render path should always have an answer for nothing came back.
08

One enum saves you ten if-statements — constrain the choice, not just the type. design

The single highest-leverage field in a schema is an enum. The moment you write badge: "new" | "sale" | "none" instead of badge: string, three things happen: the model can't invent a fourth option, your CSS only needs three classes, and TypeScript will scream if you forget a case. You've moved a whole branch of "what could the model possibly say" out of your runtime and into the contract.

free string — chaos

unbounded
badge: string
// model returns: "New!", "ON SALE",
// "limited", "🔥", "best seller"…
// now style all of them. good luck.

enum — calm

bounded
badge: "new"|"sale"|"none"
// model must pick one of three.
// .tag.new / .tag.sale — done.
// exhaustive, stylable, safe.
try it
Anywhere your UI has a finite set of states — status, tier, category, tone — make it an enum in the schema. You're not just typing the field; you're deciding the model's whole option space.
09

Stream JSON without the half-object flicker — wait for whole, render once. frontend

Vol. 22 was about streaming prose so the app breathes. JSON is the exception that proves the rule: a half-parsed object is worse than a spinner, because { "title": "Trail is not valid JSON and your render explodes. With structured output, you usually want to stream the tokens to a buffer, show a skeleton while it fills, and only swap in the real card when the object closes and validates.

useCard.ts — buffer, then commit
let buf = "";
setLoading(true);              // show the skeleton, not a partial card

for await (const delta of stream) {
  buf += delta;                  // accumulate raw text — don't render it
}

const card = safeCard(buf);     // parse + validate the *whole* thing
setCard(card);                   // one clean swap, no flicker
setLoading(false);
prose streams character-by-character. objects stream then snap into place. different jobs.
10

The trust test — would you render this object on a real page without reading it first? polish

Here's the bar. If you'd happily pipe the model's output straight into production UI without eyeballing it — because the schema constrains it, the validator catches the strays, and the fallback handles the rest — you've built it right. If you still feel the urge to console.log and squint before trusting it, a layer is missing. Find which one.
