Claude, unattended: the night I stopped babysitting my agents.

An audit of how Claude Code actually runs on my Mac, checked against the current docs. Five changes that let agents take on bigger work and stop tapping me on the shoulder. Each one comes with a prompt to try it.

— scribbled by Lupo, with 185 sessions of receipts.

I run a lot of Claude sessions at once, sometimes nine, some of them overnight. My question was simple: what keeps stopping them? So I read two weeks of my own transcripts before touching a single setting.

The receipts: 82 auto-mode denials, and 18 on 09-28 alone were outages: the safety checker was down, so it refused plain ls and head reads. My custom chief-of-staff agent ran zero times in 30 days. The GitHub connector failed to connect in every single session. And 79 commands timed out, but none since 09-07, so that one fixed itself.

Everything below is reversible. The undo is in ~/.claude/setup-changelog.md.

01

Reads that never wait on the checker.

permissions

Auto mode sends most actions to a safety classifier. When that classifier has a bad minute, even ls gets refused, and an overnight run just stalls. The docs say narrow allow rules are resolved before the classifier runs. So I listed the commands that only look and never change anything.

# ~/.claude/settings.json → permissions.allow (40 rules, excerpt)
"Bash(ls *)", "Bash(cat *)", "Bash(head *)", "Bash(grep *)",
"Bash(git status *)", "Bash(git log *)", "Bash(git diff *)",
"Bash(gh pr view *)", "Bash(gh run list *)", "Bash(launchctl list *)",
"Bash(python3 ~/Agents/tools/repo-status/status.py)"

Anything that writes, like find (it can -delete), sed, or sort -o, stays out, so it still goes through the classifier.

try it"Check the git state of every repo on this Mac and tell me which ones have work that isn't on GitHub."
02

Auto mode finally knows whose repos these are.

auto mode

By default the classifier trusts only the folder a session starts in. My old environment block had been generated from ~/Agents and never updated. It told the classifier my only source control was a folder with no remote. So pushing to my own GitHub looked like sending data somewhere unknown, and it got blocked as an "External System Write".

beforeSource control: The trusted repo (~/Agents, no remote configured)

(no $defaults, so the whole built-in list was replaced)
after"$defaults",
Source control: github.com/localwolfpackai and every repo under it…
CI/CD: Vercel; main on the client sites = production, needs my go…
Sensitive: ~/Documents, .env files, vault plugin keys…

This is additive, not looser. The built-in block rules are untouched, and my two live client sites are now named as production, so they get more protection than the generic "anything called prod" guess.

try it"Push this branch and open a draft PR." Then run claude auto-mode config and read the environment section.
03

Every denial leaves a receipt.

hooks

Claude Code has a PermissionDenied hook that fires whenever auto mode refuses something, including when the checker is down. The built-in "Recently denied" list skips those outages and doesn't survive past the session. So a tiny script now appends each one to a log.

$ tail -3 ~/.claude/state/auto-mode-denials.jsonl
{"ts": "2026-09-29 02:14", "cwd": "~/Projects/…", "tool": "Bash", "input": "…"}

It never blocks anything and fails silently. The log sits in state/, which git ignores.

try it"Read ~/.claude/state/auto-mode-denials.jsonl and propose the environment entry or allow rule that would have prevented each routine one. Don't apply anything."
04

A builder with its own desk.

subagents

My sessions keep colliding: two of them on the Margie repo means somebody switches branches under the other. The builder subagent (~/.claude/agents/builder.md) runs with isolation: worktree, so it gets its own copy of the repo. It also runs in the background and has memory: user, so it remembers build quirks between runs.

own worktree→ build + verify→ push branch→ draft PR

It never merges, deploys, or uses rm. Decisions that belong to me go in the PR under Needs Lupo, and it keeps building everything else.

try it@agent-builder "In the Margie site, add the 4px gold bar to the short-version box and an On-this-page table of contents to blog posts."
05

A verifier that can't cheat.

subagents

The session that built something always believes it works. The verifier subagent has Edit and Write taken away, so it can only run, open, screenshot, and report. It answers PASS or FAIL with one line of evidence per check, and remembers what builders keep getting wrong.

try it@agent-verifier "Check that margieluporealestate.com's blog renders on phone and desktop with no console errors, and that every post in the sitemap loads."
06

One dead connector, gone.

cleanup

The GitHub MCP server failed in every session ("does not support dynamic client registration"). Meanwhile the gh command is signed in and does everything it would have done. I removed the server instead of fixing it.

undoclaude mcp add --transport http -s user github https://api.githubcopilot.com/mcp/
07

What I left alone, on purpose.

skipped
  • Status line. I dropped it on 07-30, and iTerm's cc-status already shows each session's state.
  • Sandbox mode. It fences files and network. That would fight the LaunchAgents and dropzone, and auto mode already covers what I need.
  • A Stop hook that keeps agents going. I tried one in June and it looped. Overnight work gets a tight brief with a clear stop instead.
  • Bare /loop as a nightly routine. Routines need a stopping point and a fast way for me to judge them. Open-ended loops made the brand sandbox sloppy.
